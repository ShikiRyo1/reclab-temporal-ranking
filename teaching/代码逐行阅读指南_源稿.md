# P1 模型代码伴读：从评分到推荐服务

本稿对照 `src/reclab/data.py`、`models.py`、`metrics.py`、`rerank.py`、`train.py` 的实际源码。行号以本稿末尾的源码指纹为准；代码中的空行只负责分段，圆括号、方括号和花括号的单独收尾行并入所属语句解释。这里的数学小例子标为“教学例子”，实验数字来自 `reports/experiment/summary.json`。完整源码应与本稿一起阅读，不能只背函数名称。

默认你会读 Python 的变量、列表、循环和函数；需要补的知识是：Pandas 按条件选行、NumPy 形状与广播、稀疏矩阵、排序指标和训练／验证／测试的时间边界。读完后应能自己回答四件事：一条评分去了哪个时间窗口；一个用户为什么被算作 warm 或 cold；一个候选电影的分数怎么得来；选重排参数时有没有看测试集。

## 1. 先认清数据在五个文件之间怎么走

`data.py` 读取原始评分，按全局时间分成训练、验证、测试；`models.py` 只用训练窗口拟合三种排序器；`metrics.py` 负责相同候选范围下的比较；`rerank.py` 在 BPR 的前 100 个候选中调整排序；`train.py` 把这些动作按顺序串起来，先把验证选择写到磁盘，再评估测试集并导出服务产物。

设训练中至少有一条高分记录的用户数为 \(U\)，电影数为 \(I\)，潜在因子数为 \(d\)。本次 \(U=4865\)、\(I=3444\)、\(d=64\)。用户因子矩阵 \(P\) 的形状是 \((U,d)\)，电影因子矩阵 \(Q\) 是 \((I,d)\)，电影偏置 \(b\) 是 \((I,)\)。`P @ Q.T + b` 得到 \((U,I)\) 的分数矩阵。`b` 通过广播加到每一个用户对应的行，不会变成用户偏置。

## 2. data.py：让数据、时间和分母说同一种话

### 文件入口与 SHA-256

**L1–L10。** 模块 docstring 中的 immutable 表示本模块读入数据后不改写原始文件，leakage-aware 表示切分考虑时间泄漏。`from __future__ import annotations` 延迟解释类型标注；`str | Path` 因而容易与后续类型提示一起使用。`hashlib` 计算摘要，`Path` 组合跨平台路径，NumPy 操作时间数组，Pandas 管理评分表。空行分开标准库、第三方库和函数。

**L11–L17。** `sha256_file(path)` 输入文件路径，输出 64 位十六进制摘要字符串。L13 建立空的 SHA-256 状态；L14 用 `rb` 读取原始字节，因此换行和编码的变化也会被识别；L15 每次读 1 MiB，直到读到空字节串 `b""`。`iter(callable, sentinel)` 会反复调用 lambda，遇到 sentinel 才停止。L16 累积每块内容，L17 输出摘要。这样不用把大文件一次全部放进内存；摘要用于确认同一份输入，不能代替来源和许可证检查。

### 把原始文件读成可检查的表

**L20–L28。** `load_movielens(directory)` 返回两个 DataFrame：评分表和电影目录。L21 明确不读人口统计字段，也不重编码原始 ID。L22 把字符串转为 `Path`。`ratings.dat` 每行用双冒号 `::` 分隔，因此 L24 指定 Python 解析引擎；L25 补上原文件没有的四个列名。L26–L27 用 `int32` 保存 ID、`int8` 保存 1–5 分、`int64` 保存 Unix 秒，减少内存且保留时间范围。返回前没有把评分二值化，低分记录还要用于“看过就排除”。

**L29–L32。** 读取 `movies.dat` 的电影 ID、标题、类型三列。`latin-1` 对齐文件中的文字编码，避免带重音字符的片名报错。类型字段此时仍是 `Drama|Comedy` 一类字符串；真正服务用的 `list[str]` 在 `train.py` 中生成。

**L33–L41。** L33 先查任意缺失值，再查同一个用户与电影组合是否重复；任一问题就报错，避免一条偏好重复计数。L35–L36 检查评分都在闭区间 [1,5]。L37–L38 不允许电影目录里同一 ID 出现两次；L39–L40 检查每个被评分电影都有元数据。L41 返回 `(ratings, items)`。这些检查回答“输入能否按当前假设解释”，并不证明评分没有抽样偏差。

### 全局时间切分

**L44–L50。** `temporal_split` 输入评分表和两个比例，输出三个新表及审计信息字典。训练默认 70%，验证默认 15%，剩下约 15% 用于测试。L49 的链式不等式要求三个窗口都保留正的比例，L50 对错误配置直接报错。docstring 的重点是相同时间戳不能跨窗口。

**L51–L57。** 取所有时间戳并排序得到一维数组 `times`，至少要有三条记录。L54 用 `int(N * 0.7) - 1` 找训练分位位置，L55–L57 找 85% 的位置；减 1 是从“第几个”换成从 0 开始的下标。这里确定的是全体记录的时间界线，并非逐用户随机抽取。比例只是定位时间点的办法，最终行数可能略偏离整齐的 70/15/15。

**L58–L64。** 训练包含 `timestamp <= train_cutoff`；验证同时满足“大于训练界线”和“不晚于验证界线”；测试严格晚于验证界线。三个布尔条件互斥。`.copy()` 建立独立表，后面的修改不会悄悄影响原表。相同时间戳全部落在同一侧；如果大量并列时间导致某个窗口为空，L63–L64 报错，而不是偷偷换随机切分。

**L65–L74。** 记录两个整数时间界线、三组行数和明确带 UTC 时区的 ISO 日期。`unit="s"` 表示原值单位为秒；误写为毫秒会让日期完全不同。L74 返回四个对象，调用方要按相同顺序接收。本次得到 700148 / 150029 / 150032 条，训练界线为 `2000-11-22T03:06:26+00:00`，验证界线为 `2000-12-10T04:20:42+00:00`。

### 历史与可达目标

**L77–L82。** `history_map` 按用户分组，把每组电影 ID 转成 Python 整数集合，输出 `dict[int, set[int]]`。字典查用户、集合查电影都很方便。这里完全不按评分筛选：某人给一部电影打 1 分，仍说明他已经评分过；推荐列表也应排除它。排序分组使输出组织稳定，集合的意义仍是成员关系，不是顺序。

**L85–L93。** `eligible_targets` 输入未来窗口、训练可推荐电影 ID、截止到窗口开始前的历史，以及默认阈值 4；输出每位用户的可达相关电影集合和完整分母。L90 保留评分至少为 4 的未来记录；L91 把训练电影列表变成集合；L92–L93 初始化目标字典与两类排除计数。当前实验配置固定阈值 4；训练入口会拒绝其他阈值。若另开实验改变正例定义，训练、评价和协议保护都必须一起改。

**L94–L101。** 逐条遍历高分未来记录，`itertuples(index=False)` 不携带 DataFrame 行索引。先判断电影是否在训练候选目录；不在则计入 `absent`。在目录内但已出现在窗口前历史的，计入 `already_seen`。两者都不是才加入目标集合。`setdefault(user, set())` 第一次遇到该用户时创建集合，以后复用；`.add(item)` 防止同一目标重复。`if/elif` 让两类排除互斥：本函数优先归入“目录外”。

**L102–L111。** 返回值中既有全部未来记录／用户数，也有高分记录／用户数、两种排除量、最后可达目标数和失去全部可达目标的用户数。`sum(map(len, targets.values()))` 累加每个用户的目标集合大小。这样当 Recall 的分母减少时，读者知道减少了什么。本次测试有 83152 条高分记录，151 条不在训练目录，0 条属于已见项目，剩下 83001 条；1486 位高分用户中 1 位没有可达目标。

教学检查：某用户训练时给电影 A 打 2 分，测试时 B 得 5 分但 B 不在训练目录。A 属于 seen；B 属于 out-of-catalog。这个用户没有可达测试正例，就不进入排序指标的平均值，但必须出现在排除统计中。若只报告成功进入指标的用户数，会掩盖这部分覆盖限制。

## 3. models.py：三个可比较的排序器与一个服务接口

### 从正例到稀疏矩阵

**L1–L17。** 模块说明同时承担 CPU 训练和普通数组推理。NumPy 做矩阵运算，Pandas 提供表类型，`scipy.sparse` 保存稀疏交互矩阵，`history_map` 统一已见定义，`rerank` 复用离线与服务端的排序逻辑。L11–L15 列出模型产物必须存在的键：版本、ID 与位置映射、因子与偏置、电影元数据、历史、流行度、长尾掩码和选定重排权重。缺其中任何一项，都不能把产物当作可用模型。

**L18–L26。** `fit_rankers(train, config)` 返回产物草稿和三种分数。Cornac 只在函数内部导入，所以 Docker 推理镜像不用安装训练框架。L22 从训练窗口筛选高分正例；L23–L24 去重、排序得到稳定的用户／电影 ID。L25–L26 生成“原始 ID → 矩阵下标”的字典。ID 可能不连续，因此不能直接把电影 ID 当数组下标。

**L27–L32。** 把每条正例中的原始 ID 映射成行号与列号；同一位置放入 1，创建形状为 \((U,I)\) 的 CSR 稀疏矩阵 \(X\)。CSR 只显式存储非零位置，适合大部分用户没有评价大部分电影的情况。`float32` 每个数占 4 字节。这里不是把所有缺失评分当成确定的差评，只是用“是否有高分正例”构建训练交互。

### Popularity 与 SAR-style

**L33–L40。** L33 对 \(X\) 按列求和得到电影正例次数 \(c_i\)，再 `.ravel()` 展开成 \((I,)\)。L34 的 \(X^T X\) 是 \((I,I)\) 的共同喜欢人数矩阵，随后转成稠密数组；本例 3444 项可在本机完成，这种做法不适合直接扩到百万电影。L35 用广播计算并集人数 \(c_i+c_j-c_{ij}\)；L36–L38 在分母大于零处计算 Jaccard 相似度，其余置零。L39 把自身相似度清零；L40 计算 \(XS\)，把用户喜欢过的电影对其他电影的相似度相加，得到 \((U,I)\) 分数。

Jaccard 公式是 \(S_{ij}=c_{ij}/(c_i+c_j-c_{ij})\)。教学例子：A 有 4 人喜欢，B 有 3 人喜欢，2 人同时喜欢，两者并集是 5 人，相似度为 0.4。源码注释和报告称它为 SAR-style，因为本实现采用二值偏好、Jaccard 和零对角线，没有完整复刻微软 SAR 的所有时间衰减与参数。原仓库复现另有独立实验，不能把这里的数字替换成上游复现数字。

### BPR 与 ID 顺序

**L41–L45。** 生成 `(user, item, rating)` 三元组交给 Cornac。两个 ID 转成字符串与库内部键保持一致；第三项固定为 `1.0`，代表正例交互，而不是原来的 4 分或 5 分。生成器逐条提供记录；`seed` 控制数据集相关随机状态。

**L46–L52。** 从配置取 BPR 参数：`k=64` 是隐因子维度，`max_iter=100` 是训练轮数，学习率为 0.01，L2 正则系数为 0.01，`use_bias=True` 保留电影偏置。`num_threads=1` 减少并发 SGD 带来的执行顺序变化；固定种子仍不意味着任意平台、任意库版本逐位相同。`verbose=False` 关闭每轮进度，`.fit(data)` 才真正训练。

**L53–L59。** 注释提醒 Cornac 按记录首次出现的顺序分配内部位置，未必等于我们的升序 ID。`u_order`、`i_order` 查询内部映射，L56–L58 按我们需要的顺序重新取因子和偏置。L59 的分数为 \(s_{ui}=p_u^Tq_i+b_i\)。这里保留偏置很关键：如果训练时用了 bias，导出时忘了加回，API 排序就不是已评估的 BPR。

**L60–L62。** `np.lexsort((items, -popularity))` 最后一个键是主排序键，因此先按流行度降序，再按电影 ID 升序打破并列。先把全部电影标为长尾，再把最热门的 `ceil(0.2 * I)` 个标为 False。这里“长尾”是训练电影目录的后 80%，不是累计贡献 80% 交互之后的电影；两种定义不能混用。

**L63–L73。** 把 ID、映射、因子、偏置、正例次数和长尾标记写进普通字典。`seen_items` 来自全部训练评分并转为稳定排序的列表。`training_positive_counts` 另存每位用户的正例数，供活动分组；它与“已见电影总数”含义不同。记录 Cornac 版本。L73 同时返回三组分数，流行度为 \((I,)\)，SAR-style 和 BPR 为 \((U,I)\)。此时产物尚缺标题、最终版本号和选定权重，后面由 `train.py` 补齐，不能立刻拿这个草稿启动服务。

### 产物校验

**L76–L82。** `validate_artifact` 先用集合差找缺失字段，错误消息列出具体键；再限制 schema 为整数版本 1。schema 是序列化结构版本，`model_version` 则区分具体训练产物，两者用途不同。

**L83–L91。** 取用户与电影数，检查两个因子数组都是二维，用户行数正确且潜在维度相同；再检查电影因子行数和元数据条数。偏置、流行度、长尾标记都必须恰为 \((I,)\)，防止形状广播悄悄制造错误。异常意味着不应让 readiness 返回可用。

**L92–L100。** 对浮点参数逐个检查有限性，NaN 和正负无穷都不能作为正常模型参数；ID 不得重复。L97–L100 根据 ID 数组重新构造预期映射，和产物字典逐项比较。维度正确但映射错位同样危险，会把甲用户的向量当成乙用户的向量。

**L101–L106。** 元数据中的电影 ID 必须与同一位置的模型 ID 相同；`zip(..., strict=True)` 防止两边长度不同时静默截断。重排权重必须在 [0,1]。成功返回用户数、电影数与因子维度，便于审计。HTTP 层还需验证标题与类型字段符合响应类型；核心矩阵校验并不代替完整 API schema 校验。

### 推荐请求是怎样得到结果的

**L109–L119。** `recommend` 接收产物、可选用户 ID、返回条数、可选重排权重和类型偏好，返回电影字典列表。`None` 权重表示使用验证集选好的默认值；用户显式传 0 时必须保留 0，不能把它当作 False 而替换成默认值。L115 单独排除 `bool`，因为 Python 中布尔值是整数子类。k 允许 1–50，权重必须有限且在 [0,1]。docstring 明确分数不是点击概率，也不是预计评分。

**L120–L129。** 在用户映射中找位置。位置可能为 0，所以 L121 写 `is not None`，不能用 `bool(user_position)`。已知用户用其长度 64 的向量乘 \((64,I)\) 电影矩阵，再加偏置；未知用户用 `log1p(popularity)` 回退并强制重排权重为 0。对非负计数，log1p 严格单调，因此回退排序和按原始次数排序一致；它不表示模型学会了这个陌生用户的偏好。

**L130–L133。** 遍历该用户全部已见电影。若电影也在训练目录里，就把对应候选分数置为负无穷；目录之外的历史跳过。后续排序主动排除非有限值，因此这些电影不会出现在结果中。模型冷用户也可能有低分训练历史，使用同一份历史过滤仍有必要。

**L134–L142。** 有类型偏好才执行过滤。L135 收集目录中的全部合法类型；不认识的值直接报错。L138–L141 对每部电影检查其类型集合与请求是否有交集，所以多个偏好之间采用 OR：请求 Drama 和 Comedy 时，符合任一个即可。没有交集的分数置为负无穷。此函数约定 `items[*].genres` 已经是字符串列表；不要直接塞入原文件里的竖线字符串。

**L143–L146。** 调用离线实验使用的同一个 `rerank`。候选池取配置值，缺配置时默认 100，且至少等于请求 k；否则可能想返回 50 项却只提供 10 个候选。这里先做已见和类型过滤，再取候选池，所以过滤不会把原 top100 全部清空却漏掉第 101 项的合法电影。

**L147–L158。** 把数组位置还原成原始电影 ID、标题和类型；`score` 是候选池中归一化后的混合分数，`base_score` 保留原始 BPR 或流行度回退分数。`int/float/bool` 把 NumPy 标量转成容易 JSON 序列化的 Python 类型。`reason` 表明个性化或冷启动策略。严格配对 `positions` 与 `mixed`，保证分数对应正确电影。候选不足时返回少于 k 项；没有候选则返回空列表，不复制电影凑数。

## 4. rerank.py：把相关性损失限制在验证集允许的范围

**L1–L6。** 文件说明强调 deterministic，即相同输入下排序稳定；bounded candidate pool 表示只在 BPR 预先召回的有限候选内调整。只依赖 NumPy，训练和服务都可调用。

**L7–L13。** `rank_topk(scores, item_ids, k)` 返回数组位置而非电影 ID。先检查 k 为正、两个数组长度一致；`isfinite` 去掉 NaN 和正负无穷；`flatnonzero` 取得还可参与排序的位置。`lexsort` 先按分数从高到低，再按原始 ID 从小到大。返回最多 k 个有效位置。如果只剩 3 个候选，k=10 也只返回 3 个，不会出现伪造的重复项。

**L16–L20。** 新颖度取 \(n_i=1-\log(1+c_i)/\max_j\log(1+c_j)\)，其中 \(c_i\) 仅使用训练正例次数。`log1p` 比先加 1 再取 log 更适合数值计算；`initial=0.0` 也允许空数组求最大值。所有次数为 0 时返回全 1，避免除零。对于本实验训练目录，至少有一个正例；最大流行电影的新颖度为 0，低频电影更高。这是流行度变换，不代表电影内容新、上映时间新或用户一定会喜欢。

**L23–L30。** `rerank` 输入一位用户的全部候选分数、电影 ID、流行度、k、权重和池大小，返回 `(positions, mixed_scores)`。L28–L29 限制权重和池大小；L30 先按原模型取前 `pool_size` 个可推荐电影。低于这个池的电影不会被新颖度单独提上来，这一设计保留了基本的相关性门槛。

**L31–L36。** 空池时返回两个空数组。非空时取候选原分数，计算极差；极差大于 0 就做 min–max 归一化 \(r_i=(s_i-s_{min})/(s_{max}-s_{min})\)，否则相关性统一置 0。混合分数为 \(m_i=(1-w)r_i+wn_i\)。归一化范围仅是当前用户的当前候选池，所以不同用户的 `score=0.8` 不可直接比较。

**L37–L40。** 注释说明 w=0 必须保留原始高精度顺序，避免归一化后的舍入差异改变并列关系；这时直接用候选池原顺序。w>0 才按混合分数重排，并再次以 ID 打破并列。最后截取 k 项，返回它们在全电影数组中的位置及对应混合分数。

教学例子：A 的归一化相关性为 1、新颖度为 0；B 的相关性为 0.8、新颖度为 1。w=0.2 时 A 得 0.8，B 得 0.84，因此 B 可以超过 A。这个例子只说明公式如何工作，不是本次某位真实用户的日志。这个模块没有实现基于内容相似度的 MMR，也没有直接计算列表内多样性；不能仅凭“冷门更多”就宣称类型多样性已提升。

## 5. metrics.py：评价的分母、群体和不确定性

### 单用户指标

**L1–L10。** 模块说明是 full-catalog ranking：先给全部训练候选评分，再由重排池决定可调整范围；没有从大量负例中只抽几个容易的负例来评价。导入目标过滤、排序与重排。`rank_topk` 当前未直接调用，它的逻辑由 `rerank` 使用；该导入不改变结果。

**L11–L21。** `ranking_metrics` 输入推荐 ID 列表、非空相关集合和 k。空相关集合无法定义本项目的 Recall 分母，因此报错；重复推荐也报错。L17 取前 k 项，将命中标为 1，未命中标为 0。L18 的 `arange(2, len(hits)+2)` 对应排名 \(r=1,2,\ldots\) 时的 \(\log_2(r+1)\)。L19 计算最多 `min(k, number_of_relevant_items)` 个理想命中的折损和。L20 返回 DCG/IDCG，L21 返回命中数／全部可达相关电影数。Recall 的分母不是 k，也不是用户全部评分数。

教学例子：相关集合为 {A,C}，推荐前三项 [A,B,C]，DCG=1+1/log2(4)=1.5，IDCG=1+1/log2(3)，所以 NDCG≈0.9197，Recall=2/2=1。若只返回 [A]，Recall=0.5，NDCG≈0.6131；不能因为列表只有一个命中项就说 NDCG=1。

### 同一套协议比较所有排序器

**L24–L34。** `evaluate` 输入产物、某种排序器的分数、未来评分表、窗口开始前历史，以及 k、重排权重和池大小。返回聚合字典与逐用户表。L31 取得可达目标和排除统计；L32 为 warm/cold 分别建推荐电影去重集合，用于覆盖率。L33–L34 只看训练正例计数确定活动量中位数，本次为 52；不能用测试活动量给用户分组。

**L35–L43。** 按用户 ID 遍历，使输出顺序稳定。有训练向量的是 warm，没有的是 cold。输入分数若是一维，说明当前评估 popularity；即使用户有向量也用流行度。没有向量的用户无论比较哪个模型，都回退为流行度并用零重排权重。其他情况从该用户行取分数并使用指定权重。`.copy()` 很重要，否则后面把已见分数改成负无穷时会污染共享分数矩阵。

**L44–L52。** 逐一屏蔽窗口开始前看过的电影，调用相同重排函数，位置转回原始 ID，计算当前用户指标，再把推荐电影加入其群体的去重集合。验证历史只有训练窗口；测试历史包含训练和验证窗口。这改变的是可推荐集合，模型参数仍冻结在训练界线。

**L53–L67。** 每个用户记录 ID、群体与活动切片。训练正例数严格大于中位数才归 high；等于中位数归 low。保存可达正例数与实际返回数，方便检查分母。长尾占比是被推荐位置中 `long_tail_mask=True` 的平均值；没有推荐时记 0。`mean_log_novelty` 使用平滑流行度概率的自信息：\(-\log_2[(c_i+1)/(\sum_jc_j+I)]\)。这是 bit 单位的平均量，与 `rerank.py` 的 [0,1] 新颖度变换不是同一个数。最后 `**measured` 把 NDCG 和 Recall 两个键展开进入该行。

**L68–L81。** 所有行变成 DataFrame。先保存目标分母、目录规模、训练活动量中位数；再分别计算 warm/cold 用户数、用户平均 NDCG／Recall、用户平均长尾占比、目录覆盖率、独特推荐项数和平均自信息。群体没有用户时准确率类指标为 `None`，不能装成 0；覆盖率仍可为 0。coverage 的分母是全部训练候选电影数。此实验所有已评估用户都能返回 10 项，所以“用户平均长尾占比”也等于全部推荐位置中长尾比例；候选不足时两种聚合通常不相等。

**L82–L87。** 仅对 warm 用户按高／低活动切片，保存每组人数、NDCG 和 Recall；cold 已单独报告，不混进低活动 warm。返回 summary 和逐用户 frame。当前发布协议固定 `k=10`，输出键因此叫 `ndcg_at_10`；训练入口会拒绝其他 k。若将来扩展，指标键名、图、文档和协议保护也必须一起更新。

### Bootstrap 与配对比较

**L90–L100。** `bootstrap_interval(values, draws=1000, seed=42)` 将输入转成 float64。空输入返回两个 None；否则固定随机数生成器，重复 1000 次有放回抽取与原用户数相同的下标，每次计算平均值。最后取均值分布的 2.5% 和 97.5% 分位数作为 percentile interval。抽样单位是用户指标，不是单条评分；否则评分多的用户会在不确定性估计中被重复放大。

**L103–L112。** `paired_comparison` 只保留两种方案的 warm 用户和三项指标，按 user_id 一对一合并。`validate="one_to_one"` 拦截重复用户；长度检查拦截群体不一致。一定要先对齐用户，再相减，不能假定两个 CSV 的行顺序恰好相同。

**L113–L123。** 对 NDCG、Recall、长尾占比逐项计算“changed 减 base”的用户均值和配对 bootstrap 区间。每次重抽的是用户差值，所以保留了同一用户在两个方案间的关联。得到的区间描述当前训练结果与当前时间窗口下的用户抽样变化；不包括重新训练、更换随机种子或换一个日期窗口的不确定性。

本次 BPR+novelty 相对 BPR 的 NDCG 差值是 -0.003194，95% 配对区间 [-0.004972,-0.001335]；长尾比例差为 +0.004338，即 +0.434 个百分点，区间 [0.003037,0.005643]。Recall 的差值区间跨 0。因此应说“以较小的 NDCG 损失换到更多长尾位置”，不能说“所有指标都提升”。563 位 cold 用户和 922 位 warm 用户来自不同群体，两个群体的 NDCG 高低也不能直接当作策略优劣结论。

## 7. 数学与代码之间再走一遍

BPR 对训练三元组 \((u,i,j)\) 比较一个高分电影 i 与抽样未观察电影 j。设 \(\Delta=s_{ui}-s_{uj}\)，一次更新的教学损失写为

\[
\ell=-\log\sigma(\Delta)+\frac{\lambda}{2}\left(\|p_u\|^2+\|q_i\|^2+\|q_j\|^2+b_i^2+b_j^2\right).
\]

\(\sigma(z)=1/(1+e^{-z})\)，所以 \(-\log\sigma(\Delta)=\log(1+e^{-\Delta})\)，实现上可以用 softplus 避免指数溢出。令 \(a=\sigma(-\Delta)\)，则

\[
\nabla_{p_u}\ell=-a(q_i-q_j)+\lambda p_u,\quad
\nabla_{q_i}\ell=-ap_u+\lambda q_i,\quad
\nabla_{q_j}\ell=ap_u+\lambda q_j,
\]
\[
\partial\ell/\partial b_i=-a+\lambda b_i,\qquad
\partial\ell/\partial b_j=a+\lambda b_j.
\]

梯度下降用“参数减学习率乘梯度”。因此正例向量向用户偏好靠近，负例向量往相反方向调整；L2 项收缩参数。这里 j 是抽样未观察项，不能把它解释成用户确认不喜欢的电影。Cornac 在每次抽样更新时处理相应参数的正则项；它与把全量目标上的正则项只算一次不是随意可互换的缩放，重写优化器时要重新核对。

本项目另有真实单元测试，使用 \(p=(0.2,0.3),q_i=(0.4,0.1),q_j=(0.1,0.2),b_i=0.05,b_j=-0.02,\lambda=0.01\)，分别计算上面解析梯度和步长 \(10^{-6}\) 的中心有限差分。两者在绝对误差 \(10^{-8}\) 内一致。这证明这段推导与教学损失一致；Cornac 实际训练仍由其实现完成，不能把测试说成我们从零写了 Cornac 的优化器。

# 模型测试代码伴读：断言在保护什么

本章解释五个测试文件的全部非空源码行。测试中的小型评分表和模型产物是人工构造的教学数据，不是 MovieLens 真实用户记录。它们故意放大一个具体错误，使测试失败时能直接定位；完整 MovieLens 实验另行检查真实规模和实际效果。

`assert 条件` 表示条件为假时测试失败。`pytest.raises(...)` 表示这段调用必须抛出指定异常；没有异常同样算失败。`pytest.approx(...)` 和 `np.allclose(...)` 用允许的数值误差比较浮点数，避免把正常舍入当作模型错误。测试通过只说明已覆盖情形满足断言，不能自动推出任意输入、任意版本或实际用户体验都正确。

## 1. test_data.py：时间边界和目标分母

**L1–L7。** NumPy 构造候选 ID 数组，Pandas 构造小评分表，pytest 提供异常与参数化检查。只导入 `eligible_targets`、`history_map`、`temporal_split` 三个待测函数。这组测试不需要下载或训练模型，因而容易快速重跑。

**L8–L10。** 第一项测试给出 `[1,1,2,2,3,3,4,4]` 八条时间戳，用 50% 训练、25% 验证切分。相同时间成对出现，能暴露把时间相同的记录按数组位置随意拆开的错误。输出分别接为训练、验证、测试和审计字典。

**L11–L13。** L11 检查训练最后时刻早于验证最早时刻，且验证最早时刻早于测试最早时刻；L12 检查分区条数之和等于输入；L13 检查训练切点确实为 2。结合这个固定输入，预期三组是时间 {1,2}、{3}、{4}。这些断言不是任意时间数据的形式证明；完整运行另有 `validation.timestamp.max() < test.timestamp.min()` 的审计结果。

**L16–L18。** 第二项把十条记录全部设为同一个时间戳。按严格时间规则不可能得到三个非空窗口，因此必须报 `ValueError`，且错误消息包含 `empty partition`。`match` 检查异常原因，避免另一种无关 ValueError 也让测试误过。它防止程序遇到难切的时间数据就静默改成随机切分。

**L21–L25。** 构造用户 1 的历史：电影 10 得 1 分、20 得 5 分。未来窗口包含：用户 1 再给 10 高分、给 30 四分、给目录外 99 五分；用户 2 给 20 两分。训练候选仅 `[10,20,30]`。先调用 `history_map(past)`，再传入目标过滤函数，覆盖两个模块的衔接。

**L26–L29。** 正确目标仅为 `{1: {30}}`。电影 10 虽然历史只得低分，但属于已见，要计 1 条；99 在目录外，也计 1 条；只有 30 是可达正例。用户 2 的未来低分没有进入正例集合。四条断言共同防止“只过滤历史高分”和“悄悄扔掉目录外目标却不记分母”两类错误；没有检验其他正例阈值，因此当前实验仍明确固定阈值 4。

**L32–L35。** `@pytest.mark.parametrize` 会用三组参数分别运行同一个函数，因此这里计 3 项测试。`(0,.1)` 没有训练份额，`(.9,.2)` 总份额超过 1，`(.5,0)` 没有验证份额，均必须报错。`range(10)` 提供充足且不同的时间戳，让失败原因来自比例而不是时间并列。参数化减少重复代码，同时保留每组参数的独立失败报告。

本文件共 6 项测试。学习检查：把 `history_map` 改成只保存评分至少 4 的历史，哪项会先失败？第三个函数的 `truth == {1:{30}}` 会失败，因为电影 10 被错误当成新目标。这比“函数返回一个字典”更能说明我们要防的回归。

## 2. test_models.py：固定小产物检查真实服务语义

### 产物为什么要这样造

**L1–L9。** `copy` 用于深复制嵌套字典与 NumPy 数组，避免一个故障案例污染下一例。NumPy/Pandas 创建数据，pytest 管理异常。导入训练、推荐、产物校验三个函数。这里没有依赖 API，直接测试模型核心。

**L10–L17。** `artifact()` 每次返回一个新字典，不是 pytest fixture 装饰器。只有用户 7、电影 11/12/13；原始 ID 故意不从 0 开始，映射才是合法数组位置。用户向量为 `[1,0]`；电影向量第一维分别是 100、3、2；电影 13 另外有偏置 5。故其完整 BPR 分数应为 7，高于电影 12 的 3。这样可以发现导出后忘记加 bias 的错误。

**L18–L22。** 电影 11、13 是 Drama，12 是 Comedy；用户 7 已见 11。流行度分别为 1、100、10，让回退排序与个性化排序有明显区别。长尾标记仅是测试数据约定；这份产物不是由真实训练的 top20% 定义生成。默认重排权重设 0，避免新颖度混合掩盖对基础分数的判断。

### 推荐列表与错误输入

**L25–L29。** 已知用户 7 请求 3 项。电影 11 虽然分数 100 最高，但已见，必须排除；13 的点积 2 加偏置 5 得 7，超过 12 的 3。L27 期待恰为 `[13,12]`，同时检查过滤、排序和候选不足时不重复凑满；L28 验证原始分数为 7；L29 验证策略明确写 `personalized_bpr`。它不能证明这些分数对应真实喜爱概率，也不能证明大数据上的排名效果。

**L32–L35。** 未知用户 999 请求 Drama 类型。电影 12 尽管流行度最高，但类型不匹配；剩下 13 的流行度 10 大于 11 的 1，故结果 `[13,11]`。用户 999 没有用户 7 的历史，因此电影 11 可以出现。逐项检查 reason 为 cold_start_popularity，防止把陌生用户的回退结果标成个性化。

**L38–L42。** 请求不存在的类型应抛出含 `Unknown genre` 的 ValueError；传 NaN 权重也应抛出 ValueError。NaN 的危险在于很多普通大小比较会返回 False，若未先用 `isfinite` 检查，错误分数可能进入后续排序。测试只覆盖这里的异常值，不等于所有请求参数都已覆盖；HTTP 层还有单独的字段校验测试。

### 产物完整性

**L45–L47。** 首先校验正确产物，预期得到 1 位用户、3 部电影、2 个因子，确认校验器不会无差别拒绝所有输入。后续故障案例都从这个已通过的产物出发。

**L48–L55。** 深复制后把电影偏置缩短为长度 2，必须拒绝；再从原始正确产物重新深复制，把用户因子设为正无穷，也必须拒绝。普通字典浅复制仍可能共享内部数组，因此这里不能只写 `bad=good.copy()`。断言说明这些尺寸和数值错误会被拦截，不证明任意损坏的 pickle 都能安全加载；反序列化前仍必须信任来源。

### 小规模真实 BPR 拟合

**L58–L62。** 构造 3 位用户、3 部电影、6 条高分交互。用户按 9、2、4 的首次出现顺序排列，而预期导出的升序是 2、4、9；电影首次出现顺序也不是完整升序。这专门触发训练库内部遇见顺序与项目外部 ID 排列不同的情形。

**L63–L66。** 设定 4 个因子、2 轮训练、学习率和正则各 0.01、bias 开启、种子 42。这里确实调用 Cornac 拟合，不是用 mock 假装训练成功；数据很小，因此仍适合作为快速测试。2 轮的目的只是验证训练接口与数组衔接，不追求推荐质量。

**L67–L71。** 检查导出用户与电影 ID 都按升序；重建 `user_factors @ item_factors.T + item_biases`，与导出 BPR 分数近似一致；每部电影有两个正例，所以 popularity 应为 `[2,2,2]`。这些断言覆盖导出顺序约定、分数重建和计数。重建使用的仍是同一组导出参数，不能单靠这项断言证明每个库内部原始分数都正确对齐；实际代码中的显式 `uid_map/iid_map` 转换和后续审阅也是证据的一部分。

**L74–L82。** 第一例把电影 11 和 12 的索引交换，尺寸仍完全正确；校验器必须以 `ID mapping` 原因拒绝。第二例保留索引和因子，却把首条元数据 ID 改为 99，必须以 `metadata order` 原因拒绝。两例防止“接口有数值输出但对应错电影标题”的静默错误。它们没有检查任意标题文本的真实性；标题内容校验与来源核对仍在其他层完成。

### BPR 梯度的数值核验

**L85–L87。** 八维参数依次排为用户向量两维、正例向量两维、负例向量两维、正例偏置和负例偏置。正则系数 0.01。把位置固定下来，才能确认解析梯度与数值梯度逐项比较的是同一参数。

**L89–L91。** 内部 `loss(theta)` 先计算正负分差，再返回 `logaddexp(0,-gap)` 加 `0.5*lambda*(theta@theta)`。`logaddexp(0,z)` 数值稳定地计算 \(\log(1+e^z)\)；`theta@theta` 是平方和。因此损失确切为 \(-\log\sigma(\Delta)+\lambda\|\theta\|^2/2\)，正则梯度是 \(\lambda\theta\)，不是 \(2\lambda\theta\)。

**L93–L97。** 切片取出三组向量，重新计算分差，`q=1/(1+exp(gap))` 即 \(\sigma(-\Delta)\)。`np.r_` 依次连接用户、正例、负例和两项偏置梯度：`-q*(positive-negative)`、`-q*u`、`q*u`、`-q`、`q`；然后统一加正则梯度。注意负例向量和负例偏置的符号与正例相反。

**L98–L101。** 选步长 \(h=10^{-6}\)。`np.eye(8)` 的每一行是一个单位方向 e，循环只给当前坐标加减 h，用中心差分估计导数，得到长度 8 的向量。`allclose` 同时采用绝对容差 \(10^{-8}\) 和相对容差 \(10^{-7}\)，检查每项解析梯度与差分近似一致。这是当前非退化点的数值核验；不构成对所有参数的形式证明，也不是重新实现或验证 Cornac 的全部 SGD、负采样和多线程细节。

本文件共 7 项测试。学习检查：如果把 L96 中负例向量的 `q*u` 写成 `-q*u`，哪些坐标会先不一致？负例向量两维会与中心差分不符；这正是逐坐标核验比只看“损失下降了”更容易定位的地方。

## 3. test_metrics.py：手算标准比复制实现更有用

**L1–L7。** NumPy 提供 log2 和数组，Pandas 构造逐用户结果表，pytest 提供近似比较及异常检查。导入单用户排名指标、bootstrap 和配对比较三个函数。

**L8–L11。** 推荐 `[1,2,3]`，相关集合 `{1,3}`，K=3。第一、第三项命中，故 DCG=1+1/log2(4)=1.5；理想两项相关放在前两名，IDCG=1+1/log2(3)。L10 用手算比值作独立预期值；L11 检查命中全部两个相关项，所以 Recall=1。这能发现 NDCG 折扣下标或理想分母错误，但只覆盖二值相关性，不证明分级相关性 NDCG 已实现。

**L14–L15。** 相关集合有三项，实际只返回一项且命中，Recall 必须为 1/3。它专门防止误用“返回数量”或 K 作 Recall 分母。如果错写成命中数／返回数，此例会错误得到 1。

**L18–L22。** 空相关集合没有本项目定义下可用的指标分母，应明确抛异常；重复推荐 `[1,1]` 也要抛异常，不能让同一正例被重复算命中。这不表示业务 API 应当崩溃：上层应先筛选可评估用户，并按唯一候选生成列表。

**L25–L28。** 五个用户指标都为 1 时，无论怎样有放回抽样，均值都为 1，区间应精确 `[1,1]`。再用 0.0 到 0.9 的数组重复调用默认种子，检查结果可重放。这里将 bootstrap 重复次数降为 100 以便快速测试；正式实验使用 1000。可重复只说明随机过程固定，不证明区间在所有真实分布中都有恰好 95% 覆盖率。

**L31–L37。** 基准表有用户 1 和 2 的 warm 指标；`.iloc[::-1]` 反转行序后复制，并把每位用户 NDCG 加 0.1。配对函数应按 user_id 对齐，平均差仍为 0.1。如果只按行位置相减，个体差值会错误。这里均值碰巧仍可能不变，因此代码中的一对一合并与后续的群体检查也要一起理解；该单一均值断言不能完整证明逐用户配对正确。

**L38–L39。** 刻意只保留 changed 表的一位用户，要求错误消息含 `identical`。它防止把不同人群的均值变化当作同一批用户的改进。普通无配对均值差可以有其他合理用途，但不是本项目这个函数的契约。

本文件共 5 项测试。学习检查：95% bootstrap 区间跨 0 能否证明模型没有差别？不能。它只说明当前抽样假设和精度下的区间仍包含零；也可能是样本不足。当前项目另外报告均值、用户数与区间，避免把显著性当成效果大小。

## 4. test_rerank.py：候选边界和关闭开关

**L1–L6。** NumPy 创建分数与 ID，pytest 管理参数化错误检查；导入基础 top-k、训练计数新颖度和混合重排函数。本组都用小数组，不训练模型。

**L7–L9。** 分数 `[2,2,-inf,nan]` 对应 ID `[9,3,2,1]`。无穷与 NaN 不可参与排序；两个有效项同分时 ID 3 先于 9，所以返回数组位置 `[1,0]`。测试特意检查位置，不把它误当作原始 ID。即使请求 k=10，也只能返回两个有效位置。

**L12–L16。** 分数 `[4,2,4,-inf]`、ID `[9,8,3,1]`，热门程度刻意不同。w=0 时新颖度不能影响排序，分数 4 的 ID 3 与 9 按 ID 先后排列，最后是 8。结果 `[3,9,8]` 检查关闭新颖度开关后是否忠实保留基础顺序；不能只检查“推荐数仍为 3”。

**L19–L24。** 原分数让电影 1、2、3 依次排名，候选池只取 2 项；流行度为 100、1、0。w=1 完全按新颖度重排池内候选，因此 2 应排在 1 前；电影 3 虽然更冷门，但在池外，绝不能被重排直接召回。L23 和 L24 分别检查池内变化和池外边界。它不证明池大小 2 或正式实验的 100 是全局最优值。

**L27–L29。** 输入次数 0、1、100，检查新颖度严格随流行度下降。这是定义应该具有的单调性，不使用任意预期小数，因而不太受正常浮点微差影响。它没有检验“冷门更符合用户兴趣”，后者需要真实评价数据。

**L32–L34。** 三个分数全部设为负无穷，表示已见或类型过滤后没有任何候选。应返回长度都为 0 的位置与分数数组，而不是抛排序错误、返回 NaN 或用已过滤项补满。这个模型核心行为应在 API 中表现为 `returned_k=0` 的合法结果。

**L37–L40。** 三组参数分别是权重小于 0、权重大于 1、候选池大小 1 小于 k=2，都必须抛 ValueError。装饰器展开为 3 项测试。分数和计数使用全 1，是为了让异常由参数约束触发，而非数据问题。

本文件共 8 项测试。四个文件合计 6+7+5+8=26 项，已真实执行通过。参数化的同一函数会按输入组合计多个测试；不能只数 `def test_...` 的数量。

## B. check_bpr_math.py：把手推梯度与实际数值相对照

### 目标函数与解析梯度

**L1–L12。** 模块 docstring 给出已检查的 Cornac 2.3.0 源码 URL，并明确范围：检查一个固定用户、正物品、负物品三元组的数学更新，不声称穷尽检查编译后训练器所有路径。json 保存证据，Path 定位输出，NumPy 进行向量运算。这里不调用 Cornac 训练。

**L14–L18。** objective 输入长度 11 的浮点向量和正则系数，返回单个目标值。前 3 个数是用户向量，随后 3 个是正物品，再后 3 个是负物品，最后两个是各自偏置。@ 是内积；gap 为用户对正负物品的分数差。−logaddexp(0,−gap) 等于 log sigmoid(gap)，能避免先算指数再取对数产生部分数值溢出。theta @ theta 是全部参数平方和，乘 0.5λ 后扣除，规定采用最大化目标的符号。

**L20–L25。** analytic_gradient 使用同一套分块与分数差。z=1/(1+exp(gap)) 等于 sigmoid(−gap)，也是 log sigmoid(gap) 的导数。L24 的 np.r_ 按原参数顺序拼接五块：用户的 z(q_i−q_j)、正物品的 zp、负物品的 −zp、正偏置的 z、负偏置的 −z。L25 对每个参数减去 λθ，得到完整梯度。这个小核验固定输入在普通数值范围；L23 没有宣称适用于任意极端 gap 的通用稳定 sigmoid 实现。

### 中心有限差分逐参数检查

**L27–L30。** main 选取非零、有正有负的 11 个固定参数，避免全零例子掩盖符号问题。float64 提供差分所需的精度。regularization=0.1、epsilon=10^-6、learning_rate=0.01 是核验例子的数值，不是原 notebook 的训练超参数；两者不要混淆。

**L31–L37。** analytical 保存手推公式结果，numerical 初始化相同形状的零向量。循环一次检查一个坐标；plus 与 minus 都复制原 theta，不能在原数组上累计扰动。分别对同一个坐标加、减 epsilon，再用两个目标值之差除以 2epsilon。这就是中心差分，相比只往一个方向扰动更能抵消一阶截断误差。

**L38–L43。** error 是每个坐标差值取绝对值后的最大数，能发现某一个偏置或向量分量写错而平均值掩盖的问题。before/after 检查本例沿正确梯度迈一小步后目标是否增加。三个 norm 值分别是原参数范数、只做负正则收缩后的范数、错误地用正号放大后的范数。这里暂时隔离似然项，专门检验正则方向。

**L44–L46。** 三个 assert 分别要求最大误差 <10^-7、目标上升、范数收缩方向正确。实际最大误差约 1.095×10^-10；目标从 −0.7551046480 增至 −0.7463151328；正确正则使范数从 0.8560957890 降至 0.8552396932。assert 是实验检查，正常命令不加 Python -O；-O 会关闭断言，因此不应以优化模式执行验收脚本。

### 证据输出与解释边界

**L47–L54。** result 保留 PASS、目标约定、完整输入参数、差分步长、两组 11 维梯度、最大误差、目标变化和范数变化。NumPy 数组用 tolist 转成 JSON 列表。另存 x=1 时的导数 0.2689414214，便于直接检查正负号；该值应为正。

**L55–L58。** 保存实际检查过的源代码位置与结论。结论区分“原 notebook 展示公式错误”和“Cornac 实现更新正确”；scope 再说明只核验一个三元组，避免把有限差分通过夸大成全部实现正确的证明。

**L59–L62。** 从脚本位置找到项目 reports/baseline，必要时创建父目录，以 UTF-8 输出 bpr_gradient_check.json 并打印同一份结果。输出 JSON 足够别人重算这个小例子，无需访问任何真实用户评分。

## E. setup.ps1：环境准备脚本逐行解释

**L1–L4。** param 声明两个可覆盖的字符串参数：Workspace 控制外部源码、数据和缓存所在目录，Python 指向用来创建环境的 Python 3.12。默认值对应本机已经核验的位置；换电脑时通过命令参数提供实际路径。声明类型 [string] 便于 PowerShell 做输入转换，括号收尾属于参数块。

**L5–L8。** ErrorActionPreference='Stop' 让 PowerShell cmdlet 遇到错误时停止。它不能保证所有原生 exe 的错误都会变成异常，所以后面还检查 LASTEXITCODE。Commit 固定上游版本；Join-Path 用目录与子路径组合目标。PSScriptRoot 是当前 setup.ps1 所在目录，所以 EnvPython 始终是这份 baseline/.venv 的解释器，不会指向主项目 .venv。

**L13–L16。** 只在 SourcePath 不存在时克隆仓库。Test-Path 的 LiteralPath 按字面路径处理，不把字符当通配符。New-Item -Force 准备父目录，Out-Null 仅隐藏对象输出。Git 的 --filter=blob:none 按需取得文件对象，--no-checkout 暂不铺开工作文件；其后必须选择所需目录并 checkout。克隆失败时立即 throw，防止继续执行一个不完整源码树。

**L24–L27。** 对新建或已有源码都读取 HEAD，再检查 Git 成功且提交一致。不同版本时提示保留原目录并选择独立工作区；不会自动硬重置或清除修改。这里验证提交编号，运行器还会在正式执行前验证相关源码 Git diff。
