# Frozen temporal evaluation protocol

Status: defined before any validation/test result. Config: configs/temporal_1m.json. This is our experimental extension, not the upstream random-split reproduction.

1. Load immutable official MovieLens 1M ratings.dat and movies.dat; preserve archive SHA256. Rating>=4 is an observed positive. Missing ratings are not demonstrated dislikes; no causal click/conversion claims are possible.
2. Choose timestamp cutoffs from the global sorted rating timestamps at 70% and 85% row positions. Put all equal timestamps on the same side: train<=t1, validation t1<time<=t2, test>t2. Never use future data for training, catalog eligibility, popularity or tail definitions.
3. Train once on all training positives. Candidate catalog is exactly items with at least one training positive; users with any training positive are warm. For validation exclude any training-rated items; for test exclude any item rated in train OR validation. The model is intentionally frozen at t1 (no test-period update/retraining), while known-history filtering advances to t2. All models use the same candidate catalog and exclusion set in each window.
4. Primary ranking cohort: warm users with >=1 future positive inside the eligible catalog and not already observed at prediction time. Macro-average per-user Recall@10 and binary NDCG@10 against full eligible catalog, not sampled negatives. Report cold-start users separately using popularity fallback, and report every filtered user/positive denominator so warm metrics cannot hide coverage limitations.
5. Baselines: training positive popularity; our binary Jaccard item-item SAR-style score X*(X'X)/(c_i+c_j-overlap), self-similarity zero, without upstream time decay; Cornac BPR with frozen 64 factors/100 epochs/lr0.01/reg0.01/bias/seed42/one thread. Own SAR-style is not asserted numerically identical to upstream SAR.
6. Long-tail items = all except top ceil(20% of catalog) ranked by training positive count, ties by item_id. Candidate pool for BPR reranking = top100 unseen items. Normalize BPR scores to [0,1] within that pool; novelty=1-log1p(popularity)/max(log1p(popularity)). Mix (1-w)*normalized_score+w*novelty. This is an application of novelty reranking, not a claimed novel algorithm.
7. Validation only: grid w=[0,.02,.05,.1,.2,.35,.5]. Keep configurations with warm macro NDCG>=98% of w0 baseline; choose greatest long-tail exposure, then NDCG, then smaller w. Save chosen configuration and hash before running test. w0 remains available, so no feasible improvement is an honest result. No test-driven weight/model/epoch changes.
8. Report warm and cold NDCG/Recall, catalog coverage, long-tail share, average log novelty and head/tail activity slices. Tail exposure does not prove user satisfaction. Compute paired user bootstrap (1000 draws, seed42) 95% interval for test NDCG/Recall differences between chosen re-ranker and plain BPR, and absolute CIs; paired differences preserve user correspondence. This measures sampling variability for one split and seed, not uncertainty over all future periods/training runs.
9. Save aggregate summary, validation sweep, selected configuration, user-level metrics locally, split IDs/hashes, artifacts, true runtime/package/hardware metadata, load/save parity and deterministic finite-difference gradient checks. Source user IDs and interactions remain ignored local data/artifacts; only aggregate report enters public repo.
10. Serving artifact remains frozen t1 for honest demo consistency; its artifact seen_items uses only training observations. Evaluation's additional validation history mask is an evaluation feature and explicitly differs from static serving history. A future production refresh is outside this offline experiment.
