# 项目1再审：查出的缺口、补修和结论边界

本轮按用户保存的40条要求重新检查。原交付的代码与模型运行证据成立，但“逐条全部通过”说得过满：有5项教学与记录缺口。再审先补内容、再检查文件和页面，不用一份新的摘要替代教案。

## 这次实际重新验证了什么

本地测试重新执行50项，全部通过；运行中的Docker服务重新接受17项真实HTTP检查，全部通过。另一路检查从原始评分重新构造时间切分、训练目录和候选分母，用冻结模型数组独立计算四种方法的暖/冷用户指标、7个验证权重及1,000次成对bootstrap。15项独立检查均通过，指标绝对差在1e-12容差内。

这不是重新训练。原训练代码、模型hash、实验汇总和原42+35页Word/PDF均保留；两次完整训练的历史记录也重新比对一致。上游执行Notebook的原代码、26个单元及8项原指标被逐一核对，没有将本轮检查时间冒充原运行时间。

证据：[独立数据与数学核验](../reports/release/reaudit_20261021_baseline.json)、[真实HTTP](../reports/release/reaudit_20261021_http.json)、本地JUnit文件 `reports/release/reaudit_20261021_tests.xml`。原负载与故障恢复记录仍可用，本轮没有把它们说成新做的压测。

## 怎样理解通过

当前代码、冻结实验、本地部署、教学覆盖与最终页面的验收由 `reports/release/reaudit_20261021.json` 给出。文档内容修补与历史记录恢复是两件事：补册完成后，教学缺口可以关闭；缺失的旧时刻不能恢复，必须保留 `PASS_WITH_LIMITS`，不能写成无条件100%通过。

40条还包含至少两个项目、后续顺序与用户学习目标。P1核验通过不代表整个作品集已完成，也不代表学习者已独立掌握。公共云部署、GitHub Actions、在线业务收益和HTML浏览器交互仍没有已验证结果；这些边界沿用原交付，不用本轮再审覆盖。

## 对求职材料的影响

模型指标没有变，简历应继续写真实的离线取舍：长尾占比1.84%→2.28%，NDCG相对损失1.31%。新增内容使面试官更容易追查实验条件、代码和故障检查，也使学习者能从环境搭建开始重跑。不能把多写一本手册说成新的模型改进。

项目2接着解决不同的问题：自然语言回答如何使用正确工具、计算正确指标、引用真实证据并在证据不足时停下来。它会引用P1已经核验的接口和汇总证据，不把P1换一个聊天界面当成第二个完成项目。
